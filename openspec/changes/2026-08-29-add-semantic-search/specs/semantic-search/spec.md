## ADDED Requirements

### Requirement: 自然文で記事を検索できる
システムは検索クエリを受け取ったとき、クエリを埋め込みベクトルに変換し、pgvector による類似度検索で関連度の高い記事を返さなければならない（SHALL）。

#### Scenario: 意味ベースの検索が成功する
- **WHEN** ユーザーが検索ボックスに「Rustの非同期処理でつまずくところ」と入力して検索する
- **THEN** タイトルに該当キーワードを含まない記事であっても、内容が意味的に近い記事が上位に表示される

#### Scenario: 検索結果が0件
- **WHEN** 収集記事と意味的に関連のないクエリが入力される
- **THEN** 「該当する記事がありません」という空状態 UI が表示される

#### Scenario: 空のクエリ
- **WHEN** 検索ボックスが空の状態で検索が実行される
- **THEN** 検索は実行されず、通常の記事一覧が表示される

#### Scenario: AI サービスが応答しない
- **WHEN** 検索実行時に AI サービスがエラーまたはタイムアウトを返す
- **THEN** エラーメッセージが表示され、既存の記事一覧・フィルタ機能は引き続き利用できる

### Requirement: 検索結果を既存フィルタと併用できる
システムは検索実行時、`source` および `status` クエリパラメータが指定されている場合、検索結果に対してそのフィルタ条件を適用しなければならない（SHALL）。

#### Scenario: ソースフィルタとの併用
- **WHEN** 「Zenn」ソースフィルタが選択された状態で検索が実行される
- **THEN** 検索結果のうち Zenn の記事のみが表示される

#### Scenario: 状態フィルタとの併用
- **WHEN** 「お気に入り」状態フィルタが選択された状態で検索が実行される
- **THEN** 検索結果のうちお気に入り登録済みの記事のみが表示される

### Requirement: 検索状態が URL に反映される
システムは検索が実行されたとき、URL の `q` クエリパラメータを更新しなければならない（SHALL）。

#### Scenario: 検索クエリが URL に反映される
- **WHEN** ユーザーが「LLMのコスト削減」と入力して検索する
- **THEN** URL に `?q=LLM%E3%81%AE...` が含まれる

#### Scenario: 検索クエリを含む URL を直接開く
- **WHEN** `q` パラメータを含む URL に直接アクセスする
- **THEN** 該当クエリの検索結果が表示される

### Requirement: 検索の前提をユーザーに明示する
システムは検索 UI において、検索対象が記事の要約情報であり、ソースにより情報量が異なる旨を表示しなければならない（SHALL）。

#### Scenario: 検索 UI に注記が表示される
- **WHEN** ユーザーが検索ボックスを利用する
- **THEN** 「検索は記事の要約情報に基づきます」といった注記が視認できる位置に表示される

### Requirement: AI サービスの認証情報をクライアントに露出しない
システムは AI サービスへのリクエストを Next.js の API Route 経由で行い、AI サービスの API キーをクライアントサイドに送出してはならない（SHALL NOT）。

#### Scenario: ブラウザから API キーが観測できない
- **WHEN** ユーザーが検索を実行し、ブラウザの開発者ツールでネットワークリクエストを確認する
- **THEN** リクエストの送信先は自サイトの `/api/search` であり、AI サービスの URL および API キーは含まれない
